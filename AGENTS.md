# AGENTS.md — инструкция для ИИ-агентов (и людей)

Этот файл — главный источник правил для любого агента, который работает с репозиторием (Claude Code, Codex, Cursor и др.). `CLAUDE.md` импортирует его целиком.

## Продукт в пяти строках

Сайт **одного собачьего приюта** в России.

1. **Нужды:** админы публикуют, что нужно купить или оплатить (корм, лекарства, ремонт забора, работа плотника) — с целью в ₽ и срочностью. Люди жертвуют на конкретную нужду или в общий фонд, разово или ежемесячно.
2. **Радикальная прозрачность:** каждое поступление и каждый расход видны публично, вплоть до чеков и фото результата.
3. **Собаки:** каталог с профилями. Кнопка «Хочу забрать» открывает контакты куратора (анкеты нет).
4. **Доп. фичи:** виртуальная опека (ежемесячная подписка на конкретную собаку), помощь вещами, волонтёрство.

## Стек

Next.js (App Router) · TypeScript strict · Tailwind CSS v4 · shadcn/ui · Prisma + PostgreSQL 16 · Better Auth · pg-boss (фоновые задачи) · S3-совместимое хранилище (MinIO в dev, Yandex Object Storage в prod) · React Email · CloudPayments · Vitest · Playwright.

Версии Node и pnpm закреплены в `mise.toml` (Node 24, pnpm 10). Установка: `mise install`.

## Инварианты — нарушать нельзя

1. **Деньги — только целые копейки** (`Int`, поля с суффиксом `Kop`). Никаких `float` для сумм. Форматирование в ₽ — только через общий хелпер.
2. **Книга операций — append-only.** В таблицы `Ledger*` пишет **только** модуль `src/server/ledger`. Никаких `UPDATE`/`DELETE`: ошибки исправляются сторнирующей проводкой. Сумма проводок каждой транзакции = 0. Подробно — [docs/ledger.md](docs/ledger.md).
3. **Любой вебхук и любая денежная операция идемпотентны** (уникальный `dedupeKey` / `idempotencyKey`). Повтор не должен создавать вторую проводку.
4. **Блокировки в фиксированном порядке:** `Donation → Need → Subscription` (`SELECT … FOR UPDATE`), чтобы не было дедлоков.
5. **Сначала проверка прав, потом действие.** Каждая server action и route handler вызывают `can(user, permission)`; действия сотрудников пишутся в `AuditLog`.
6. **Персональные данные:** не логировать email/телефоны/карты; на публичных чеках ПДн закрашены (флаг `redacted`); имя донора показывается только с его согласия. Подробно — [docs/legal.md](docs/legal.md).
7. **Секреты не коммитятся.** Только `.env.example` с пустыми значениями. Не читай `.env`.
8. **Языки:** тексты интерфейса, письма, документация, задачи и PR — **на русском**; код, идентификаторы, имена веток и коммиты — **на английском**.
9. **Без внешних сервисов вне РФ для персональных данных** (Google Analytics, облачный Sentry, иностранные email-провайдеры) — см. ADR-0004.

## Соглашения по коду

- Структура: `src/app` (маршруты), `src/server/<домен>` (бизнес-логика, только сервер), `src/components/ui` (shadcn), `src/components/<домен>` (доменные компоненты), `src/lib` (общие утилиты).
- Страницы и server actions — тонкие; логика — в `src/server/<домен>`.
- UI-компоненты — shadcn/ui в стиле `base-nova` (Base UI, не Radix): вместо `asChild` — проп `render`. `cn()` импортируй только из `@/lib/utils`; если `shadcn add` принёс импорт из пакета `cn` — замени импорт и удали зависимость `cn` (ESLint это ловит).
- Next.js 16: сверяйся с документацией установленной версии в `node_modules/next/dist/docs/`, а не с памятью — API между мажорными версиями меняются.
- Валидация входа — zod-схемы рядом с action. Формы — react-hook-form + zod.
- Публичные страницы — Server Components + ISR, инвалидация через `revalidateTag`.
- Время хранится в UTC, показывается в часовом поясе приюта (настройка).
- Русские склонения — через общий хелпер `plural()`, а не тернарниками.
- Новые зависимости — только если без них никак; объясни выбор в PR.
- Комментарии — по делу, на английском; не пересказывай код.

## Процесс работы над задачей

1. **Бери задачу** только с меткой `agent-ready` и только если все задачи из «Зависимости» / «blocked by» закрыты. Метка `needs-human` — не для агента.
2. **Ветка:** `<type>/<номер>-<короткий-slug>`, например `feat/42-need-status-machine`. Типы: `feat`, `fix`, `chore`, `docs`, `refactor`, `test`.
3. **Коммиты:** маленькие, осмысленные, Conventional Commits на английском (`feat(needs): add status machine`).
4. **PR:** заголовок на русском или английском, тело по шаблону `.github/pull_request_template.md`, обязательно `Closes #N`. Не пушь в `main` напрямую и не делай force-push.
5. **Если задача неясна или противоречит docs** — не додумывай молча: оставь комментарий в задаче с вопросом и вариантом решения по умолчанию.
6. **Если в ходе работы нашлась отдельная проблема** — заведи новую задачу (скилл `new-issue`), а не расширяй текущий PR.

## Definition of Done

- [ ] Все критерии приёмки из задачи выполнены.
- [ ] `pnpm format:check`, `pnpm typecheck`, `pnpm lint`, `pnpm test` — зелёные (их же проверяет CI); для пользовательских сценариев — e2e.
- [ ] На новую логику есть тесты (на денежную — обязательно, включая конкурентность и повторы).
- [ ] UI проверен в браузере: mobile 375 px и desktop, светлая и тёмная тема, клавиатура, пустые/ошибочные состояния.
- [ ] Миграции БД обратимы или явно описаны в PR; seed обновлён, если менялась схема.
- [ ] Задачи с меткой `money-critical` прошли ревью `ledger-auditor` **и** человека.
- [ ] Документация в `docs/` обновлена, если поменялось поведение или решение (новое решение — новый ADR).
