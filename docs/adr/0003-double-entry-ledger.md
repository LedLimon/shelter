# 0003. Книга операций по двойной записи, append-only

- Статус: Принято
- Дата: 2026-10-08

## Контекст
Прозрачность — главная ценность. Нужно, чтобы любая публичная цифра (собрано, потрачено, остаток фонда) выводилась из проверяемых записей, переплаты/остатки/недостачи/возвраты были видны, а ошибки нельзя было «тихо» исправить.

## Решение
- Таблицы `LedgerAccount`, `LedgerTransaction`, `LedgerEntry` (знаковые суммы в копейках).
- Триггеры в SQL: запрет UPDATE/DELETE, сумма проводок транзакции = 0, запрет записи в закрытый месяц.
- Исправления — только сторно (`REVERSAL`).
- Писать в книгу может только `src/server/ledger`; у каждой проводки уникальный `idempotencyKey`.
- `Need.collectedKop` — кэш, сверяется с книгой еженощно.

Подробно — [docs/ledger.md](../ledger.md).

## Последствия
- Любой баланс воспроизводим и проверяем; аудит «из коробки».
- Код денежных операций сложнее; обязательны интеграционные тесты на конкурентность и идемпотентность, ревью `ledger-auditor`.

## Рассмотренные альтернативы
- Поле `collected` у нужды + таблица платежей — проще, но нельзя доказать корректность и показать движение остатков между нуждами и фондом.
