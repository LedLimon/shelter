# 0002. Платёжный провайдер — CloudPayments

- Статус: Принято
- Дата: 2026-10-08

## Контекст
Пожертвования в России: карты (Мир), СБП, ежемесячные подписки (общий фонд и виртуальная опека), надёжные вебхуки. Приют — одна организация (НКО/ИП).

## Решение
CloudPayments, за интерфейсом `PaymentProvider` (`src/server/payments`), чтобы при необходимости подключить ЮKassa.

Причины:
1. **Встроенные рекурренты**: подписку ведёт CloudPayments (`recurrent` в виджете), сам списывает и повторяет, шлёт вебхук `Recurrent`. В ЮKassa автоплатежи нужно инициировать самим (свой планировщик) и отдельно согласовывать.
2. **Вебхук `Check`** до списания — можно проверить invoice и сумму.
3. **Подписанные вебхуки (HMAC)**; у ЮKassa — только allowlist IP и повторный запрос платежа.
4. Широко используется благотворительными организациями, есть тарифы для НКО, виджет с Мир, СБП, SberPay, T-Pay; CloudKassir — если понадобится фискализация.

## Последствия
- Заявку на подключение подаём сразу (ORG-2): тестовые ключи выдают быстро, одобрение — недели.
- Смена карты в подписке = новая подписка (`replacesId`).
- Для dev/CI нужен `FakeCloudPayments` и симулятор вебхуков.

## Рассмотренные альтернативы
- ЮKassa — запасной вариант (см. выше).
- Сбор на карту / реквизиты с ручным вводом — без автоматической прозрачности и рекуррентов; остаётся как «ручное поступление» в админке.
